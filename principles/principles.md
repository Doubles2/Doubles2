# 원칙

스킬이 판단할 때 기준으로 삼는 원칙이다. 스킬은 Step 1에서 이 파일과 링크된 원칙 파일을 **새로 읽는다**.
외워 둔 내용을 쓰지 않는다. 원칙이 바뀌어도 스킬을 고칠 필요가 없게 하려는 것이다.

출처: Lauren Tan의 brainmaxxing 원칙 16개 중 다섯 개를 골라, 이 repo의 공부 스킬
(book-study · book-voice · pragmatic-programmer · effective-python)에 맞게 다시 썼다.

- [[encode-lessons-in-structure]] — 같은 지시를 두 번 쓰게 되면 스크립트·템플릿·체크로 바꾼다.
- [[prove-it-works]] — 보고나 요약 말고 산출물(실행 출력, 만든 페이지, git diff)을 직접 확인한다.
- [[guard-the-context-window]] — 컨텍스트는 다시 채울 수 없다. 필요한 것만, 필요할 때 읽는다.
- [[never-block-on-the-human]] — 되돌릴 수 있는 일은 하고 나서 보여 준다. 스킬 수정과 git만 먼저 묻는다.
- [[subtract-before-you-add]] — 기본 행동은 빼기. 더하기 전에 겹치는 것부터 합치거나 지운다.

## 원칙끼리의 관계

- subtract → encode: 먼저 빼고, 그래도 반복되는 것만 구조로 만든다.
- encode ↔ guard: 구조로 옮기면 지시문이 줄고, 지시문이 줄면 컨텍스트가 남는다.
- never-block ↔ prove-it-works: 묻지 않고 했으면 결과를 직접 확인해서 보여 준다.
