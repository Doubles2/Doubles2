# 파이썬 코딩의 기술대로 코딩하기

파이썬 코드를 쓸 때 『파이썬 코딩의 기술』(개정2판)의 Better Way를 기본 규칙으로 삼는다.
사용자는 이 책을 공부 중이다. 코드를 보고 "이건 BetterWay 몇 번이구나"를 알아볼 수 있게 하는 것도 목적이다.

## 작업 순서

1. **환경 확인**: 대상 파이썬 버전을 먼저 본다(`python3 --version`, `pyproject.toml`, `.python-version`).
   이 Mac은 `python3` = 3.13(pyenv), `/usr/bin/python3` = 3.9. 책은 3.8 기준이다.
   버전 때문에 쓸 수 없는 문법(예: 3.8 미만의 `:=`)은 쓰지 않는다.
2. **프로젝트 규칙 우선**: 이미 있는 코드의 스타일·린터 설정(ruff, black, flake8)이 책과 다르면 프로젝트를 따른다.
   책 규칙은 프로젝트가 정하지 않은 부분을 채운다.
3. **작성**: 아래 "늘 지키는 규칙"대로 쓴다. 특정 영역(클래스 설계, 동시성, 테스트 등)을 다루면
   `references/better-ways.md`에서 해당 장을 읽고 따른다.
4. **자체 점검**: 다 쓴 뒤 아래 체크리스트로 한 번 훑는다. 실행할 수 있으면 실행해서 확인한다.
5. **설명**: 사용자에게 결과를 말할 때, 코드에 적용한 주요 규칙을 `BetterWay N`으로 짧게 짚는다
   (예: "None 대신 예외를 던졌어요(BetterWay 20)"). 모든 줄마다 달지 말고 눈에 띄는 2~4개만.

## 늘 지키는 규칙 (자주 쓰는 것)

**기본기 (1장)**
- PEP 8을 따른다. 이름은 `snake_case`/`CapWords`/`ALL_CAPS`, `if not seq:`로 빈 값 검사, `is None`. (BW2)
- 문자열 형식화는 f-문자열. `%`나 `str.format`은 쓰지 않는다. (BW4)
- 한 줄에 우겨넣은 복잡한 식은 도우미 함수로 뺀다. `or`/`and` 트릭보다 `if/else`. (BW5)
- 인덱스 대신 언패킹(`for name, score in items`), `range(len())` 대신 `enumerate`, 나란히 돌 땐 `zip`(길이가 다를 수 있으면 `strict=True` 또는 `itertools.zip_longest`). (BW6–8)
- `for`/`while` 뒤 `else` 블록은 쓰지 않는다. (BW9)
- 값을 얻고 바로 검사하는 반복은 대입식 `:=`로 줄인다. 단, 읽기 어려워지면 쓰지 않는다. (BW10)
- `bytes`와 `str`은 프로그램 경계에서만 인코딩·디코딩하고 안쪽은 `str`로 다룬다. (BW3)

**리스트와 딕셔너리 (2장)**
- 슬라이스에서 `0`과 `len(a)`는 생략(`a[:5]`, `a[5:]`). 시작·끝·증가값을 한 슬라이스에 같이 쓰지 않는다. (BW11–12)
- 여러 조각으로 나눌 땐 `first, *rest = ...` 같은 별표 언패킹. (BW13)
- 정렬은 `sort(key=...)`. 여러 기준은 튜플 키, 숫자 방향을 섞을 땐 `-`. (BW14)
- 없는 키는 `in` + `KeyError`보다 `dict.get(key, default)`. 개수 세기는 `collections.Counter`. (BW16)
- 기본값 리스트·집합이 필요한 dict는 `setdefault`보다 `defaultdict`. 키마다 기본값이 다르면 `__missing__`. (BW17–18)

**함수 (3장)**
- 실패를 `None`으로 알리지 말고 예외를 던진다. 반환 타입은 애너테이션으로 밝힌다. (BW20)
- 값 네 개 이상을 튜플로 반환하지 않는다. 작은 클래스나 `NamedTuple`/`dataclass`로. (BW19)
- 선택 옵션은 키워드 인자로, 헷갈리는 인자는 키워드 전용(`*`)·위치 전용(`/`)으로 강제. (BW23, 25)
- 기본값에 `[]`, `{}`, `datetime.now()`를 쓰지 않는다. `None` + 독스트링으로. (BW24)
- 데코레이터는 `functools.wraps`로 감싼다. (BW26)

**컴프리헨션과 제너레이터 (4장)**
- `map`/`filter`+`lambda` 대신 컴프리헨션. 하위 식(for·if)이 세 개 이상이면 풀어 쓴다. (BW27–28)
- 결과가 크거나 끝이 없으면 리스트 대신 제너레이터(`yield`, 제너레이터 식). (BW30, 32)
- 인자를 여러 번 순회해야 하면 이터레이터가 들어왔는지 방어한다. (BW31)
- 이터레이터 조합은 `itertools`부터 찾는다. (BW36)

**클래스 (5–6장)**
- dict 안에 dict 안에 리스트처럼 내장 타입을 깊게 중첩하지 말고 클래스로 나눈다. (BW37)
- 간단한 훅은 클래스 대신 함수(또는 `__call__`)를 받는다. (BW38)
- 부모 초기화는 `super().__init__()`. 기능 합성은 작은 믹스인. (BW40–41)
- 비공개(`__x`)보다 보호(`_x`) 관례. getter/setter 대신 평범한 애트리뷰트, 나중에 필요하면 `@property`. (BW42, 44–45)
- 메타클래스보다 클래스 데코레이터·`__init_subclass__`. (BW48–51)

**동시성·강건성·테스트·협업 (7–10장)**
- 블로킹 I/O는 스레드(`ThreadPoolExecutor`), CPU 병렬은 `concurrent.futures`의 프로세스 풀, 대량 I/O 동시성은 `asyncio`. 공유 상태는 `Lock`/`Queue`. (BW53–64)
- `try/except/else/finally`를 역할대로 나누고, 재사용할 정리 동작은 `with` + `contextlib`. (BW65–66)
- 시간대는 `datetime`(+`zoneinfo`), 돈·정밀 계산은 `decimal`. (BW67, 69)
- 최적화 전에 프로파일링. 큐는 `deque`, 정렬된 검색은 `bisect`, 우선순위 큐는 `heapq`. (BW70–73)
- 디버깅 출력은 `repr`. 테스트는 `unittest`/`pytest`로 격리하고, 의존성은 목(mock)으로. (BW75–79)
- 공개 함수·클래스·모듈에는 독스트링. 라이브러리는 최상위 `Exception`을 정의하고, 타입 힌트 + 정적 분석(mypy). (BW84, 87, 90)

## 자체 점검 체크리스트

- [ ] `range(len(...))`, 인덱스로 꺼내 쓰는 루프가 남아 있지 않은가? → `enumerate`/언패킹/`zip`
- [ ] `%`·`.format` 문자열이 있는가? → f-문자열
- [ ] 실패를 `None`으로 반환하는 함수가 있는가? → 예외
- [ ] 가변 기본 인자(`def f(x=[])`)가 있는가?
- [ ] 한 줄짜리 복잡한 식, 하위 식 3개 이상 컴프리헨션이 있는가? → 도우미 함수 / 풀어 쓰기
- [ ] 튜플 반환이 4개 이상인가? → 클래스
- [ ] dict 키 확인을 `in` + 대입으로 반복하는가? → `get`/`defaultdict`/`Counter`
- [ ] 내장 타입이 3단 이상 중첩되었는가? → 클래스 분리
- [ ] 공개 함수에 독스트링·타입 힌트가 있는가?
- [ ] 실행해 봤는가? 출력이 예상과 같은가?

## 하지 말 것

- 규칙을 기계적으로 적용해 읽기 어려운 코드를 만들기(예: 억지로 끼운 `:=`). 책도 "가독성"을 최우선으로 둔다.
- 사용자가 고쳐 달라고 하지 않은 기존 코드를 책 규칙대로 전부 다시 쓰기. 바꾼 줄 근처만 맞춘다.
- 책 본문을 길게 옮겨 적기. 규칙 이름과 BetterWay 번호로 짚는다.
