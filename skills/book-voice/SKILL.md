# 책 말투로 글쓰기

사용자는 책을 한 번 읽고 밑줄을 그어 공부한다. 그 책들의 **글 느낌**으로 글을 써 주는 스킬이다.
책 문장을 베끼는 게 아니라, 책이 쓰는 **구성·말투·설명 방식**을 빌려 사용자의 주제로 새로 쓴다.

## 1. 어떤 목소리를 쓸지 고르기

| 글의 성격 | 목소리 | 참고 파일 |
|---|---|---|
| 태도·습관·원칙·조언, 팀·경력·일하는 방식 | **실용주의 프로그래머** (에세이형 조언) | `references/pragmatic-programmer.md` |
| 코드·도구·라이브러리 사용법, 기술 규칙, "A보다 B를 써라" | **파이썬 코딩의 기술** (규칙 + 코드 해설형) | `references/effective-python.md` |
| 원칙을 코드로 보여 주는 글 | 둘을 섞는다: 조언형 도입 → 규칙형 본문 | 두 파일 모두 |

사용자가 책을 지정하면 그 책을 따른다. 애매하면 위 표로 고르고, 답변 첫 줄에 어떤 목소리로 썼는지 밝힌다.

## 2. 두 책의 공통점 (어느 쪽이든 지킨다)

- 독자를 **"여러분"**이라 부르고, 본문은 **"~다" 평서체**로 쓴다. 존댓말(~요, ~습니다)로 쓰지 않는다.
- 핵심은 **명령형 한 문장**으로 따로 세운다: "~하라", "~하지 말라", "A보다는 B를 사용하라".
- 주장 → 이유 → 예 → 주의점 순서. 주장만 늘어놓지 않는다.
- 외래 용어는 처음 나올 때 한국어 뒤에 원어를 괄호로 단다: 결합도(coupling), 대입식(assignment expression).
- 끝에는 **기억할 것**을 짧게 다시 모은다.

## 3. 쓰는 순서

1. 주제에서 **한 문장 규칙(Tip)**을 먼저 뽑는다. 이게 안 나오면 글의 초점이 없는 것이다.
2. 고른 목소리의 참고 파일을 읽고 **구성 틀**을 따라 개요를 잡는다.
3. 본문을 쓴다. 비유·예시는 사용자의 실제 환경(데이터 사이언스, 리테일 수요 예측, 파이썬, 노션 공부)에서 고르면 좋다.
4. 아래 점검표로 고친다.

## 4. 점검표

- [ ] 명령형 Tip 한 문장이 눈에 띄게 있는가?
- [ ] "~다" 체로 통일됐는가? (존댓말이 섞이지 않았는가)
- [ ] 추상적인 주장마다 구체적인 예(일화·비유·코드)가 붙었는가?
- [ ] 마지막에 기억할 것·도전해 볼 것 같은 정리가 있는가?
- [ ] 책 문장을 그대로 옮긴 곳이 없는가? (짧은 용어·개념 이름 정도만 허용)
- [ ] 사용자가 정한 분량·형식(노션, 마크다운, 슬랙 등)을 지켰는가?

## 5. 하지 말 것

- 책 본문을 문단째 옮기기. 이 repo는 공개이고, 목표는 흉내가 아니라 같은 **느낌**이다.
- 번역투를 일부러 과장하기("~에 있어서", "~하는 것이 요구된다"를 남발). 책의 번역투는 자연스러운 정도만 빌린다.
- 사용자가 다른 말투(존댓말 블로그, 공문 등)를 지정했는데 책 말투를 고집하기.

3. 위 1번 표에 한 줄 추가한다.
