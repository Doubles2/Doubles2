# wiki 운영 규칙

카파시의 LLM Wiki 방식을 따른다. 사람은 무엇을 남길지 정하고, 정리·연결·목차 관리는 에이전트가 맡는다.

## 구조

| 파일·폴더 | 내용 |
|---|---|
| `index.md` | 전체 목차. 페이지마다 링크 + 한 줄 요약. 질문을 받으면 가장 먼저 읽는다 |
| `log.md` | 시간순 작업 기록. 맨 아래에 추가만 한다 |
| `문제해결/` | 겪은 오류와 해결법. 한 문제에 한 페이지 |
| `개념/` | 공부하며 정리한 개념 (모델, 기법, 지표 …) |
| `도구/` | 도구·라이브러리 사용법과 설정 (uv, MLflow, Claude Code …) |

폴더는 첫 페이지가 생길 때 만든다.

## 페이지 형식

```markdown
---
tags: [시계열, lightgbm]
updated: 2026-11-18
sources: [projects/2026-12-demand-forecast, https://…]
---
# 제목

한 줄 요약.

## 본문
…

## 관련
- [[다른-페이지]]
```

- 파일 이름은 소문자 영문과 하이픈을 쓴다 (`lightgbm-early-stopping.md`).
- 문제해결 페이지는 **증상 → 원인 → 해결 → 다시 안 겪으려면** 순서로 쓴다.
- 확인한 사실과 추측을 구분한다. 추측에는 `(추측)`을 붙인다.

## 작업

- **기록**: 새 페이지를 쓰거나 기존 페이지를 고친 뒤, `index.md`를 갱신하고 `log.md`에 한 줄 추가한다.
  새 페이지를 만들기 전에 비슷한 페이지가 있는지 먼저 찾아 그 페이지를 고친다.
- **질문**: `index.md`에서 시작해 관련 페이지를 읽고 답한다. 쓸모 있는 답은 새 페이지로 남긴다.
- **점검** (한 달에 한 번): 서로 모순되는 내용, 오래된 정보, 링크가 없는 고립 페이지,
  여러 번 언급되지만 페이지가 없는 개념을 찾아 고친다. 점검 결과도 `log.md`에 남긴다.

## log.md 형식

```
## 2026-11-18 기록 | 문제해결/uv-lock-conflict.md 추가
```

맨 앞을 `## 날짜 종류 |`로 맞춰 grep으로 찾을 수 있게 한다. 종류: 기록, 질문, 점검.
