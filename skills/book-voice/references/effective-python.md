# 파이썬 코딩의 기술 목소리

『파이썬 코딩의 기술』 개정2판(브렛 슬라킨, 길벗)을 사용자가 1~2장(BetterWay 1~18)
원본 사진으로 읽으며 관찰한 특징이다. 옆 세션(2장 BW11~18 사진 31장을 직접 읽음)의 관찰을 함께 반영했다.

**한 줄 요약**: 규칙 하나를 제목으로 세우고, 순진한 코드 → 문제 → 개선 코드를 실행 결과와 함께 단계적으로 보여 준 뒤, "기억해야 할 내용"으로 못 박는 건조하고 정확한 기술 해설.

## 구성 틀 (Better Way 하나)

1. **제목 = 규칙 한 문장**: "A보다는 B를 사용하라", "~하지 말라", "~을 알아두라", "~하려면 ~을 사용하라".
2. **기능 소개 한두 문장**: 이 기능이 무엇이고 언제 쓰는지.
3. **구체적인 상황 설정**: "예를 들어 ~하고 싶다고 하자." 예제 데이터는 한국식으로(철수·순이, 그랜저·아반떼, 바게트).
4. **순진한 코드 + 실행 결과**: 코드 블록 아래 `>>>` 다음에 출력이나 `Traceback ... XxxError: ...`.
5. **문제 지적**: "이 코드는 잘 작동하지만 ~하다", "여기서 문제는 ~라는 데 있다", "시각적 잡음이 많다".
6. **개선 코드 + 실행 결과**: 같은 기능의 Before/After를 나란히.
7. **한계·예외**: "하지만 ~한 경우도 있다." 대안이 여럿이면 "첫 번째 방법은 … 가장 보수적이고 튼튼하다 / 두 번째는 … 성능이 더 좋다"처럼 장단점을 붙여 나열.
8. **다른 규칙으로 넘기기**: "(Better way N: '제목' 참고)".
9. **기억해야 할 내용**: 불릿 3~5개. 각 불릿은 규칙형 한두 문장.
10. (선택) **Note 박스**: 본론에서 벗어난 유용한 팁 하나.

## 문장 습관

- "~다" 평서체, 담담하고 정확하다. 감탄·농담은 거의 없다.
- 판단은 비교로 말한다: "~하는 편이 더 낫다", "~보다 ~가 더 명확하다", "~을 권장한다", "꼭 필요할 때만".
- 기준은 늘 **가독성**과 **실수할 여지**: "읽기 쉽다", "의도를 분명히 드러낸다", "실수할 여지가 줄어든다".
- 수동형·번역투가 자연스럽게 섞인다: "~이 반환된다", "~하는 경우", "~하게 된다", "~에 대해".
- 용어는 한국어 + 괄호 원어: 별표 식(starred expression), 스트라이드(stride), 덕 타이핑(duck typing).
- 코드 주석은 아주 짧은 한국어: `# 짧다`, `# 여전히 같은 리스트 객체임`.
- 연결어: 하지만 · 따라서 · 다행히 · 이런 경우 · 예를 들어 · 게다가 · 반면 · 즉.

## 직접 쓴 짧은 예문 (이 목소리의 느낌)

> **판다스에서 행을 하나씩 돌기보다는 벡터 연산을 사용하라**
>
> 판다스 DataFrame에서 열 두 개를 곱해 새 열을 만들고 싶다고 하자. 파이썬에 익숙한 사람이라면 `iterrows`로 행을 하나씩 도는 코드부터 떠올릴 것이다.
>
> ```python
> totals = []
> for _, row in df.iterrows():
>     totals.append(row['수량'] * row['단가'])
> df['매출'] = totals
> ```
>
> 이 코드는 잘 작동하지만 행이 많아지면 매우 느리고, 결과를 담을 리스트를 따로 관리해야 해서 시각적 잡음도 많다. 열 단위 연산을 사용하면 같은 일을 한 줄로 표현할 수 있다.
>
> ```python
> df['매출'] = df['수량'] * df['단가']
> ```
>
> 하지만 행마다 조건이 복잡하게 달라지는 경우도 있다. 이런 경우에는 `numpy.where`나 `DataFrame.apply`를 고려하는 편이 더 낫다.
>
> **기억해야 할 내용**
> - DataFrame을 `iterrows`로 한 행씩 처리하면 느리고 코드도 길어진다.
> - 열끼리의 산술 연산은 벡터 연산으로 한 번에 표현하라.
> - 조건이 복잡하면 `numpy.where`나 `apply`를 사용하되, 먼저 벡터 연산으로 풀 수 있는지 확인하라.

설명글에 코드를 넣을 때는 가능하면 실제로 실행해 출력까지 붙인다. 책처럼 코드 블록 다음에 `>>>`와 출력을 둔다.
실행할 수 없는 코드면 출력을 지어내지 않는다.
