# Never Block on the Human

되돌릴 수 있는 일은 묻지 말고 하고 나서 보여 준다. 되돌리기 어렵거나 사용자가 확인을 원한 일만 먼저 묻는다.

**Why:** "할까요?"를 물을 때마다 사용자는 기다리고, 작업은 멈춘다. 대부분의 일은 되돌릴 수 있으니 하고 나서 이유와 결과를 보여 주는 편이 빠르다.

**이 repo의 경계 (사용자가 정함):**

| 일 | 어떻게 |
|---|---|
| 노션 복습 페이지 만들기·고치기, 로컬 공부 파일(풀이 코드 등) | 하고 나서 보고 |
| **스킬 파일 수정** (`skills/`, `principles/`) | 바꿀 내용(무엇을·왜)을 먼저 보여 주고 확인받은 뒤 진행 |
| git 커밋·푸시, repo 생성·삭제 | `skills/git-confirm` 절차 그대로. 각각 따로, 실행 직전에 확인 |

**물을 때는:**
- 질문은 한 번에 묶는다. 왔다 갔다 하지 않는다.
- 선택지는 2~4개, 추천안을 맨 앞에 두고 이유를 한 줄로.
- 답을 코드·파일·기본값에서 알 수 있으면 묻지 않는다.

**테스트 질문:** "이걸 잘못했을 때 되돌릴 수 있나? 사용자가 이 종류의 일은 먼저 보자고 했나?"
