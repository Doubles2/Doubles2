# [MLflow 완전정복 #2-1] ML 라이프사이클 10단계, 하나씩 뜯어보기

MLflow 완전정복 2-1편. 지난 편에서 라이프사이클 10단계를 **훑고** 지나갔는데, 다시 보니 각 단계마다 목적과 할 일이 꽤 또렷하더라고요. ↵
이번엔 10단계를 **하나씩 뜯어보고**, 각 단계가 뒤에 어떤 부채를 남기는지까지 이어보겠습니다.

(구분선)

(제목1)
🎯 1. 왜 10단계를 다시 보나

(본문2)
지난 편은 **"어디서 문제가 터지나"**에 초점이 있었습니다. 그런데 문제가 왜 거기서 터지는지 알려면, 각 단계가 **정확히 무엇을 목표로 하고 무슨 일을 하는지**를 먼저 알아야 하더라고요.

(본문2)
강의 자료는 10단계를 각각 **Objective(목표)**와 **Key Activities(핵심 활동)**로 나눠 설명합니다. 이 구조가 꽤 유용해서, 같은 틀로 정리해 봤습니다.

(fig-01.png 삽입) — ML 라이프사이클 10단계를 세 국면으로 묶은 도식

(인용구)
💡 10개를 그냥 나열하면 안 외워져서, **"데이터를 만든다(1~4) → 모델을 만든다(5~7) → 모델을 운영한다(8~10)"** 세 덩어리로 묶어서 봤어요. 이렇게 보니 **MLOps가 왜 주로 뒤쪽(8~10)에서 이야기되는지**도 자연스럽게 이해됐습니다.

(구분선)

(제목1)
🧭 2. 데이터를 만든다 — 1~4단계

(제목2)
① 문제 정의 (Problem Definition)

(본문2)
**목표**는 풀어야 할 문제를 명확히 정의하는 것입니다. 여기엔 **기대하는 결과**와 **성공을 재는 지표**까지 포함됩니다.

(목록)
- **비즈니스·운영 목표 이해** — 이 모델이 무엇을 위해 존재하는지부터
- **타깃 변수 정의** — 지도학습이라면 무엇을 맞힐 것인지
- **평가 지표 선택** — accuracy, precision, recall 중 무엇을 볼 것인지

(인용구)
💡 **"지표를 여기서 정한다"**는 점이 인상적이었어요. 보통 모델을 다 만들고 나서 "그래서 뭘로 평가하지?"를 고민하기 쉬운데, 그 순서면 **지표에 맞춰 결과를 해석하는 게 아니라 결과에 맞춰 지표를 고르게** 되니까요.

(제목2)
② 데이터 수집 (Data Collection)

(본문2)
**목표**는 문제와 관련된 원천 데이터를 여러 소스에서 모으는 것입니다.

(목록)
- **데이터 소스 식별** — 데이터베이스, API, 웹 스크래핑, 센서 등
- **레이블 유무** — 필요에 따라 레이블 있는 데이터와 없는 데이터를 함께 수집
- **규제 준수** — GDPR 같은 데이터 프라이버시·보안 규정 확인

(제목2)
③ 데이터 전처리 (Data Preprocessing)

(본문2)
**목표**는 학습에 쓸 수 있도록 데이터를 정제하고 준비하는 것입니다.

(목록)
- **결측치 처리** — 대치(imputation) 또는 제거
- **정규화·표준화** — 스케일을 맞춤
- **범주형 인코딩** — 원-핫 인코딩 등
- **데이터 분할** — 학습·검증·테스트 세트로 나눔

(제목2)
④ 탐색적 데이터 분석 (EDA)

(본문2)
**목표**는 데이터의 패턴·분포·상관관계를 이해하는 것입니다.

(목록)
- **시각화** — 히스토그램, 산점도 등으로 데이터를 눈으로 확인
- **추세·이상치·편향 식별** — 숫자만 봐서는 안 보이는 것들
- **품질과 가정 검증** — 내가 세운 전제가 데이터에서 실제로 성립하는지

(인용구)
💡 순서가 **전처리(③) → EDA(④)**인 게 처음엔 어색했어요. 보통 EDA 먼저 하고 전처리하지 않나 싶었거든요. 그런데 자료의 EDA는 **"정제된 데이터가 쓸 만한지 검증하는 단계"**에 가깝더라고요. 실제로는 두 단계를 **여러 번 왕복**하게 될 것 같습니다.

(구분선)

(제목1)
🧪 3. 모델을 만든다 — 5~7단계

(제목2)
⑤ 모델 선택 (Model Selection)

(본문2)
**목표**는 문제에 적합한 알고리즘을 고르는 것입니다.

(목록)
- **후보 비교** — 회귀, 분류, 군집화 등 과제에 맞는 알고리즘들을 견줌
- **트레이드오프 고려** — 해석 가능성, 학습 시간, 확장성

(인용구)
💡 **"정확도"가 트레이드오프 목록에 없다**는 게 눈에 띄었어요. 정확도는 당연히 보는 것이고, 실무에서 모델을 가르는 건 오히려 **설명할 수 있는가 · 제때 학습이 끝나는가 · 커져도 버티는가**라는 뜻으로 읽었습니다.

(제목2)
⑥ 모델 학습 (Model Training)

(본문2)
**목표**는 학습 데이터셋으로 모델을 훈련시키는 것입니다.

(목록)
- **배치 분할** — 필요하다면 효율적 처리를 위해 데이터를 나눔
- **하이퍼파라미터 최적화** — learning rate, batch size 등을 조정
- **교차 검증** — 모델의 일반화 성능을 확인

(제목2)
⑦ 모델 평가 (Model Evaluation)

(본문2)
**목표**는 검증·테스트 데이터로 성능을 측정하는 것입니다.

(목록)
- **지표 평가** — 회귀는 RMSE, 분류는 F1 score 등
- **과적합·과소적합 확인** — 학습 성능과 검증 성능의 격차를 봄
- **베이스라인 비교** — 기준선보다 나은지 확인

(인용구)
💡 **베이스라인 비교**가 핵심이라고 느꼈어요. "accuracy 0.92"라는 숫자 하나는 아무 의미가 없고, **"제일 많은 클래스로 다 찍었을 때 0.90"**이라면 그 모델은 사실상 아무 일도 안 한 셈이니까요. 그리고 이 비교를 하려면 **이전 실험 기록이 남아 있어야** 합니다 — 여기서 슬슬 MLflow가 필요해지는 게 보입니다.

(구분선)

(제목1)
🚢 4. 모델을 운영한다 — 8~10단계

(제목2)
⑧ 모델 배포 (Model Deployment)

(본문2)
**목표**는 실제로 쓰이도록 모델을 프로덕션에 올리는 것입니다.

(목록)
- **배포 가능한 형태로 패키징** — REST API 또는 컨테이너
- **인프라 선택** — 클라우드 또는 온프레미스
- **기존 시스템과 통합**

(제목2)
⑨ 모델 모니터링 (Model Monitoring)

(본문2)
**목표**는 프로덕션에서 모델 성능을 지속적으로 추적하는 것입니다.

(목록)
- **드리프트 감시** — 데이터 드리프트, 컨셉 드리프트, 성능 변화
- **피드백 수집** — 재학습·업데이트에 쓸 근거를 모음

(제목2)
⑩ 유지보수 & 반복 (Maintenance and Iteration)

(본문2)
**목표**는 피드백과 새 데이터를 바탕으로 모델을 계속 개선하는 것입니다.

(목록)
- **재학습** — 갱신된 데이터셋으로 다시 학습
- **튜닝·교체** — 하이퍼파라미터를 다시 잡거나 새 알고리즘을 시도
- **대응** — 성능 저하나 새 요구사항 처리

(인용구)
💡 ⑩번의 활동 목록이 **⑥번(학습)·⑤번(선택)과 사실상 똑같다**는 걸 보고 "아, 이래서 사이클이구나" 싶었어요. 10단계는 끝이 아니라 **1단계로 되돌아가는 지점**이고, 그래서 이 과정을 **몇 번이고 다시 도는 게 기본값**입니다. 한 번 잘 만드는 것보다 **다시 돌기 쉽게 만드는 것**이 중요해지는 이유죠.

(구분선)

(제목1)
⚠️ 5. 그래서 뭐가 문제였나 — 4가지 한계

(본문2)
자료는 이 10단계를 **손으로** 돌릴 때 부딪히는 한계를 네 가지로 정리합니다.

(표 · 2열)
| 한계 | 내용 |
| --- | --- |
| **재현성 부족** | 수작업 프로세스와 일관성 없는 기록 탓에 예전 실험을 다시 만들기 어렵다 |
| **제한된 협업** | 팀이 각자 사일로에서 일해 손발이 안 맞고 비효율이 생긴다 |
| **수작업 프로세스** | 실험·학습·배포를 손으로 하니 오래 걸리고 실수가 잦다 |
| **확장성 문제** | 대규모 데이터로 모델과 파이프라인을 키우는 일이 복잡하다 |

(fig-02.png 삽입) — 4가지 한계가 어느 단계에서 생기는지 매핑

(본문2)
10단계를 하나씩 보고 나니, 이 네 가지가 **어느 단계에서 생겨나는지**가 좀 더 또렷해졌습니다. 재현성은 **③·⑥·⑦**에서 조건이 흩어지며 무너지고, 협업 문제는 **⑦ → ⑧ 인계** 지점에서 터집니다. 수작업은 **⑥·⑧**에 시간과 실수를 쌓고, 확장성은 **②·③·⑨**가 먼저 비명을 지릅니다.

(인용구)
💡 네 한계가 **서로 독립적이지 않다**는 게 이번에 정리하면서 보인 부분이에요. **수작업이 원인이고, 재현성 부족은 그 결과**에 가깝습니다. 협업이 안 되는 것도 결국 "남이 뭘 어떻게 했는지 기록이 없어서"고요. 그러니 **기록을 자동화하는 것 하나**로 네 개 중 세 개가 같이 풀리는 구조입니다.

(구분선)

(제목1)
✍️ 마무리 & 다음 단계

(본문2)
정리하면 ML 라이프사이클은 **데이터를 만들고(1~4) · 모델을 만들고(5~7) · 모델을 운영하는(8~10)** 세 국면이 **순환**하는 구조이고, 이걸 손으로 돌릴 때 생기는 부채가 **재현성·협업·수작업·확장성** 네 가지입니다.

(본문2)
각 단계를 뜯어보며 가장 크게 남은 건 **"기록이 없으면 아무것도 안 된다"**는 감각이었어요. 베이스라인 비교도, 재학습도, 인계도 전부 **지난번에 무엇을 어떻게 했는지**가 남아 있어야 가능합니다. MLflow가 겨냥하는 지점이 정확히 여기고요.
