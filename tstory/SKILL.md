# 티스토리 포스팅 생성

강의 자료(PDF/PPTX/문서/논문)를 받아 `doubles-won.tistory.com`의 기존 12편과
같은 톤·같은 레이아웃의 포스팅 한 세트를 만듭니다.

## 글 폴더 구조

글 하나가 폴더 하나입니다. **원본과 생성물이 짝을 이루는 게 핵심** — 나중에 수정하려면
생성물이 아니라 원본을 고쳐야 하기 때문입니다.

```
<슬러그>/
├── post.md         원고 겸 작업 지시서  ← 글 수정은 여기서
├── fig-01.html     도식 원본            ← 그림 수정은 여기서
├── fig-01.png      생성물 (render.py)
├── thumbnail.png   생성물 (thumbnail.py)
├── tags.txt        태그 입력칸용
└── build.sh        그림·썸네일 다시 만들기 + 원고 검사
```

새 글은 **현재 작업 폴더의** `output/<슬러그>/`에 만듭니다.
대화마다 작업 폴더가 달라 글이 흩어지므로, **나중에 찾을 땐 경로를 짐작하지 말고
`find ~ -name "post.md"`로 검색**하세요 (아래 "기존 글 수정하기" 참고).

## HTML을 쓰지 않습니다

**티스토리 글쓰기(기본모드)에 직접 타이핑하고 툴바로 서식을 지정합니다.**
HTML 모드는 쓰지 않습니다.

그래서 `post.md`는 단순한 원고가 아니라 **작업 지시서**입니다.
각 덩어리 앞에 어떤 스타일 프리셋인지 태그가 붙고, 그림은 들어갈 자리에 파일명이 적힙니다.

```
(제목1)
🎯 1. 왜 10단계를 다시 보나

(본문2)
지난 편은 **"어디서 문제가 터지나"**에 초점이 있었습니다.

(fig-01.png 삽입) — ML 라이프사이클 10단계 도식
```

위에서 아래로 읽으며 그대로 옮겨 적으면 글이 완성됩니다.
형식 전체는 `references/manuscript.md`를 보세요.

HTML 모드는 딱 한 경우에만 씁니다 — 프리셋이 어떤 크기를 내는지 확인할 때.
그 절차도 `references/manuscript.md`에 있습니다.

## 기존 글 수정하기

"저번에 만든 그 글 고쳐줘" 요청을 받으면:

**1. 글 폴더를 찾습니다.**

글은 대화마다 다른 폴더에 만들어져 흩어져 있습니다. **경로를 짐작하지 말고 검색하세요.**

```bash
find ~ -name "post.md" -not -path "*/node_modules/*" -not -path "*/.git/*" 2>/dev/null |
  while read f; do echo "$(dirname "$f")"; echo "   $(head -1 "$f")"; done
```

제목 줄로 어떤 글인지 확인합니다. 여러 개면 사용자에게 고르게 하세요.

`post.md`가 없고 `post.html`·`thumbnail.png`만 있는 폴더는 **이 스킬 이전에 만든 글**입니다.
그건 수정 흐름이 아니라 "발행된 글에서 원고 복원"이 필요하니, 사용자에게 그렇게 알리고
복원할지 물어보세요.

**2. 원본만 고칩니다.**

| 고칠 것 | 고칠 파일 |
|---|---|
| 문장·구성·표·목록·서식 지정 | `post.md` |
| 도식 내용·색·배치 | `fig-NN.html` |
| 썸네일 문구·회차 | `build.sh`의 `thumbnail.py` 옵션 |
| 태그 | `post.md` 마지막 줄 + `tags.txt` |

`*.png`는 **절대 직접 고치지 않습니다.** 다음 빌드에서 덮어써집니다.

**3. 다시 빌드합니다.**

```bash
bash <글 폴더>/build.sh
```

썸네일과 그림을 다시 만들고 원고 검사까지 돌립니다.

**4. 무엇을 다시 올려야 하는지 알려줍니다.**

바뀐 것만 짚어주세요 — 전부 다시 올릴 필요가 없는 경우가 많습니다.

- `post.md`만 고침 → 바뀐 **문단만** 글쓰기 화면에서 고치면 됩니다.
  어느 섹션의 무엇이 바뀌었는지 구체적으로 짚어주세요.
- `fig-NN.html`만 고침 → 그 **그림만** 교체 업로드
- 썸네일 옵션만 고침 → **대표 이미지만** 교체

## 발행된 글이 유일한 정답지입니다

톤을 맞출 때 **로컬 `post.md`(내가 쓴 초고)를 근거로 삼지 마세요.** 초고와 발행글은 다릅니다 —
저자가 자기 말투로 고쳐서 올리기 때문입니다. 반드시 발행 URL을 직접 받아 대조하세요.
`WebFetch`는 요약해버리니 **HTML을 직접 받아 파싱**해야 합니다.

```bash
curl -sL -A "Mozilla/5.0" https://doubles-won.tistory.com/<번호> -o /tmp/post.html
# entry-content 안의 h2 / h4 / p / blockquote / td / figcaption 을 뽑아 초고와 비교
```

저자가 새 글을 발행했다고 하면 **초고 ↔ 발행글을 대조해 references를 갱신**하세요.
이렇게 잡아낸 것들: 소단원은 제목3 · 표 헤더는 표의 첫 행 · 밑줄 > 굵게 ·
문단은 덩어리로 · 본문에 개인 감상 금지 · `👉 다음 편` 블록 삭제 · 표 안은 물음표/명사형.

## 경로 규칙

이 스킬은 `~/.claude/skills/tstory`로 링크돼 있어 **어느 폴더에서든** 호출됩니다.
따라서 경로를 상대경로로 쓰지 마세요.

- **스킬 자산**(scripts·assets·references) → `~/.claude/skills/tstory/…` 절대경로
- **산출물** → 사용자가 지금 작업 중인 폴더 기준 `output/<슬러그>/`

아래 예시들은 이 규칙을 따릅니다. 편의상 `SKILL_DIR`을 먼저 잡아두면 편합니다:

```bash
SKILL_DIR=~/.claude/skills/tstory
```

## 절대 규칙

1. **원고는 글쓰기 화면에 그대로 옮겨 적을 수 있어야 합니다.** 블록 태그로 서식을 지정하고,
   티스토리 툴바에 없는 서식은 쓰지 않습니다. 대단원은 `(제목1)`(=h2), 소단원은 `(제목2)`(=h3),
   본문은 `(본문2)` — **프리셋 이름이 태그보다 한 칸 앞섭니다.** → `references/manuscript.md`
2. **상단·하단 출처 문구는 예외 없이 넣습니다.** → `references/attribution.md`
3. **남의 그림을 캡처해 쓰지 않습니다.** 도식은 새로 그립니다.
   단 유명 논문 figure는 원본 + 출처 캡션. → `references/figures.md`
4. **해시태그는 글 하단에만** 한 줄로. 본문 중간에 뿌리지 않습니다.
5. **자료에 없는 내용을 지어내지 않습니다.** 특히 수치·벤치마크·인용문.
   자료가 모호하면 그렇게 쓰거나 사용자에게 물어보세요.

## 진행 순서

### 1. 자료 읽기

첨부 파일을 파싱합니다. PDF는 `anthropic-skills:pdf`, PPTX는 `anthropic-skills:pptx` 스킬을 쓰세요.
전체를 읽고 나서, 사용자에게 아래를 확인합니다 (모르면 추정치를 제시하고 승인받기):

- **시리즈명 / 회차** — 예: `MLflow 완전정복` / `#5`
- **주제 단어** — 썸네일 대형 텍스트에 들어갈 영문 한 단어
- **출처 유형** — 유료 강의 / 공개 문서 / 논문 / 사내 자료 (유형별 문구가 다름)
- **강의명·URL·라이선스**

### 2. 구성 설계 → 승인받기

`references/structure.md`의 5단 골격(개요 → 본론 → 결과 → 최종 요약 → 향후 계획)으로
섹션을 배치하고, **섹션 목록과 아이콘 제안을 표로 제시해 승인**을 받습니다.
승인 전에 본문을 쓰지 마세요.

### 3. 썸네일

```bash
python3 $SKILL_DIR/scripts/thumbnail.py \
  --series "…" --word "…" --title "…" --subtitle "…" --number N \
  --out output/<슬러그>/thumbnail.png
```

정확히 2400×1260이 나오는지 확인합니다. → `references/thumbnail-spec.md`

### 4. 본문 그림

도식은 `assets/diagram.html` 복제 후 `render.py`, 플롯은 `plotstyle.py` + matplotlib.
→ `references/figures.md`

**도식 원본은 글 폴더에 `fig-NN.html`로 저장합니다.** 임시 폴더에 두면 나중에 그림을 못 고칩니다.

```bash
python3 $SKILL_DIR/scripts/render.py \
  output/<슬러그>/fig-01.html output/<슬러그>/fig-01.png --width 1000 --height 900 --trim
```

### 5. 원고 작성

`references/voice.md`의 문체로, `references/manuscript.md`의 형식에 맞춰 `post.md`를 씁니다.
블록 태그와 이미지 표기를 정확히 지켜야 합니다.

**주의: 프리셋 이름과 HTML 태그가 한 칸씩 어긋납니다.**
대단원은 `(제목1)`(=h2, 26px), 소단원은 `(제목2)`(=h3, 23px), 본문은 `(본문2)`(=p, 16px)입니다.

빠뜨리기 쉬운 것:
- `# 제목` 한 줄 — 티스토리 제목 칸에 넣을 제목 (본문에는 안 들어감)
- 도입 인용구 2줄 — 줄바꿈 자리에 `↵` 표시 (Shift+Enter)
- 상단 출처 문구 — `(본문2 · 회색)` 태그
- 모든 `(제목1)` **앞**에 `(구분선)`
- 💡 개인 해석 인용구 **3개 이상** — 이게 없으면 이 블로그 글이 아닙니다
- 문단마다 `**강조**` 1~2개
- 리스트는 `- **용어** — 설명` 형태
- **문단은 1~2문장으로 짧게** — 손으로 옮겨 적는 글입니다
- 그림: `(fig-01.png 삽입) — 캡션` — `—` 뒤는 **독자가 읽는 캡션**입니다
- 표는 `(표 헤더)` 한 줄 + `(표 · N열)` 데이터 행. 마크다운 `| --- |` 금지
- 남의 말 인용은 `(인용구)`가 아니라 `(인용문)`
- 하단 출처 문구, 그리고 `(태그 칸 입력용)` 해시태그 한 줄

다 썼으면 검사합니다.

```bash
python3 $SKILL_DIR/scripts/check_md.py output/<슬러그>/post.md
```

없는 png를 참조하거나 안 쓰인 png가 있으면 잡아줍니다.
ERROR가 나오면 고치고 다시 돌리세요.

### 6. 해시태그

`post.md` 맨 아래(하단 출처 문구 다음)에 복사용 한 줄:

```
#MLflow #MLOps #실험추적 #모델레지스트리 #머신러닝 #ML엔지니어
```

같은 태그를 쉼표 구분으로 `tags.txt`에도 저장합니다 (티스토리 태그 입력칸용).
8~10개가 적당하고, 기존 글들은 한글·영문을 섞어 씁니다.

### 7. build.sh 저장

`$SKILL_DIR/assets/build.sh`를 글 폴더에 복사하고 이 글의 썸네일 옵션·그림 목록으로 채웁니다.
**도식 원본 HTML도 `fig-NN.html`로 글 폴더에 저장**하세요 (임시 폴더에 두면 나중에 수정 못 합니다).

```bash
bash output/<슬러그>/build.sh   # 한 번 돌려서 재현되는지 확인
```

### 8. 업로드 안내

산출물 목록과 함께 작성 절차를 알려줍니다:
글쓰기(기본모드) → `post.md`를 위에서부터 옮겨 적으며 태그대로 서식 지정 →
`(…png 삽입)` 자리에서 사진 업로드 → 대표 이미지로 `thumbnail.png` 지정 → 태그 칸에 `tags.txt` 입력.

## 환경 참고

- 썸네일·도식 렌더는 Google Chrome을 씁니다. 다른 경로에 있으면 `CHROME_PATH` 환경변수로 지정.
- 이 맥의 headless Chrome은 스크린샷을 쓴 뒤 스스로 종료하지 않아서,
  `render.py`가 파일 생성이 끝나면 직접 종료시킵니다. 정상 동작입니다.
- Pretendard 미설치 → Apple SD Gothic Neo로 렌더됩니다 (블로그 폰트 스택 2순위와 동일).
